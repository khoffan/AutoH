# แผน v2.0 — สั่งงานด้วยเสียงแบบ offline

> สถานะ: **แผน (ยังไม่เริ่มทำ)** · ต่อยอดจาก v1 (SQLite storage, ดู [storage.md](../storage.md)) · ขั้นถัดไป: [v2.1](v2.1-llm-and-system-actions.md)

## เป้าหมาย

ผู้ใช้กด hotkey ค้างแล้วพูดคำสั่ง (ภาษาไทยเป็นหลัก) ระบบทำงานทันที **โดยไม่ต้องสร้าง mode ใน config ก่อน**
เช่น "เปิดไลน์", "เปิด YouTube", "ค้นหาราคาทอง", "เข้าโหมด work"

ทุกอย่างทำงาน **offline ในเครื่อง** ไม่ส่งเสียงหรือข้อความออกไปข้างนอก

### ไม่อยู่ในขอบเขต v2.0
- ฟังตลอดเวลา / wake word
- ปิดโปรแกรม, คำสั่งระบบ (volume, lock, shutdown) → v2.1
- ตีความประโยคอิสระด้วย LLM → v2.1
- รัน shell command ใดๆ จากเสียง → **ไม่ทำในทุก version**

## ภาพรวมการทำงาน

```
[กด ctrl+alt+v ค้าง] → อัดเสียง (sounddevice)
[ปล่อยปุ่ม]          → faster-whisper แปลงเป็นข้อความ (thread แยก)
                     → intent parser (กฎ) แปลงเป็น Action
                     → action registry ตรวจ + ทำงาน
                     → แสดงผลใน status window + บันทึก logs
```

ทุกขั้นหลังปล่อยปุ่มทำใน worker thread แล้วส่งผลกลับเข้า UI ผ่าน `request_task()` เดิมใน `AutoHController` (Tk ไม่ thread-safe)

## โครงสร้างโค้ดใหม่

```
app/voice/
├── actions.py       # [shared v2.1] Action, ActionSpec, Risk, REGISTRY, tool_definitions()
├── validate.py      # [shared v2.1] resolve(): ตรวจ args + map ชื่อ → app/site/mode ที่รู้จัก
├── matching.py      # [shared v2.1] normalize ข้อความไทย/อังกฤษ + fuzzy score
├── pipeline.py      # [shared v2.1] interpret() → execute() พร้อม confirm callback
├── intents.py       # กฎแปลงข้อความ → list[Action] (v2.1 เสียบ LLM ต่อท้ายที่นี่)
├── app_index.py     # ใช้ scanner เดิมใน app/system/ (registry + Start Menu) → cache ใน DB
├── recorder.py      # push-to-talk: อัดเสียงระหว่างกดค้าง → numpy array 16 kHz mono
├── transcriber.py   # โหลด faster-whisper ครั้งเดียว (lazy) → text
└── controller.py    # ผูกทุกส่วน, เรียกจาก core/hotkey.py
```

ส่วน `[shared v2.1]` ออกแบบให้ v2.1 ใช้ซ้ำได้ทันที: กฎและ LLM ส่ง `Action` เข้า `validate.resolve()` ตัวเดียวกัน
และ `tool_definitions()` สร้าง tool schema ของ LLM จาก registry — เพิ่ม action ที่เดียว ใช้ได้ทั้งสองทาง

## Action ที่รองรับใน v2.0

| Action | ตัวอย่างคำพูด | การทำงาน | ยืนยันก่อน? |
|---|---|---|---|
| `open_app(name)` | "เปิดไลน์", "เปิด compass" | ค้นใน app index → `safe_open_app()` เดิม | ไม่ (ถ้ามั่นใจสูง) |
| `open_url(site)` | "เปิด YouTube", "เปิดเว็บ github" | ตาราง site ที่รู้จัก + `webbrowser.open` | ไม่ |
| `web_search(query)` | "ค้นหาราคาทอง" | เปิด Google search | ไม่ |
| `run_mode(name)` | "เข้าโหมด work" | เรียก logic เดียวกับ hotkey ของ mode | ไม่ |

## Intent parser (กฎ)

ภาษาไทยไม่มีเว้นวรรค จึงจับจาก **คำนำหน้า** แล้วตัดส่วนที่เหลือเป็น argument:

| ลำดับ | รูปแบบ | Action |
|---|---|---|
| 1 | `(เข้า)?โหมด <x>` / `mode <x>` | `run_mode` |
| 2 | `ค้นหา <x>` / `search <x>` / `หา <x>` | `web_search` |
| 3 | `เปิดเว็บ <x>` หรือ `เปิด <x>` ที่ x ตรงตาราง site | `open_url` |
| 4 | `เปิด <x>` / `open <x>` | `open_app` |
| — | ไม่ตรงกฎ | แจ้ง "ไม่เข้าใจคำสั่ง" + log `WARN` |

ก่อน match: ตัดคำสุภาพ (`ให้หน่อย`, `หน่อย`, `ครับ`, `ค่ะ`, `นะ`), ตัดช่องว่าง/เครื่องหมาย, lowercase

## App index + alias

- ใช้ scanner เดิม `system/registry.py` + `system/start_menus.py` + `system/normalize.py` (ตัวเดียวกับหน้า config)
- รวม app จาก mode ทุกตัวใน DB เข้า index ด้วย
- cache ไว้ในตาราง `app_index` และ rescan เมื่อเปิด app หรือกดปุ่ม "Rescan"
- **ปัญหาหลัก:** whisper มักถอดชื่ออังกฤษเป็นคำอ่านไทย ("ไลน์", "โครม", "วีเอสโค้ด")
  - มีตาราง alias เริ่มต้นสำหรับ app ยอดนิยม
  - ผู้ใช้เพิ่ม alias เองได้ในหน้า config
  - เมื่อจับคู่ไม่ได้แล้วผู้ใช้เลือกเองจาก dialog → บันทึกเป็น alias อัตโนมัติ (ระบบ "เรียนรู้")
- จับคู่ด้วย `difflib` (มีในตัว Python):
  - ≥ 0.85 → ทำทันที
  - 0.6–0.85 → dialog "หมายถึง X ใช่ไหม" (Enter = ใช่ / Esc = ยกเลิก, timeout 5 วินาที = ยกเลิก)
  - < 0.6 → "ไม่พบโปรแกรม" + ปุ่มเลือกจากรายการ

## การเปลี่ยนแปลงฐานข้อมูล (schema v2)

```sql
CREATE TABLE app_index (
    name   TEXT PRIMARY KEY,   -- ชื่อแสดงผล
    path   TEXT NOT NULL,
    source TEXT NOT NULL       -- 'startmenu' | 'mode' | 'manual'
);
CREATE TABLE aliases (
    alias  TEXT PRIMARY KEY,   -- คำที่ได้ยิน (normalize แล้ว) เช่น 'ไลน์'
    target TEXT NOT NULL,      -- ชื่อใน app_index หรือ site
    kind   TEXT NOT NULL       -- 'app' | 'site'
);
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,    -- voice_enabled, voice_hotkey, whisper_model, ...
    value TEXT
);
```

- migration: ถ้า `meta.schema_version = 1` → สร้างตารางใหม่ + seed alias เริ่มต้น → ตั้งเป็น `2`
- Export/Import JSON ขยายให้รวม `aliases` และ `settings` (ไฟล์เดิมที่มีแค่ `modes` ยัง import ได้)
- log คำสั่งเสียงลง `logs` เดิม ใช้ level `VOICE`: `heard="เปิดไลน์" → open_app(LINE) ok`

## ตัวแปลงเสียง (STT)

- ใช้ **faster-whisper** (CTranslate2, int8, CPU)
- ต้อง benchmark ก่อนเลือก model (เกณฑ์: แปลงประโยคสั้น ≤ 2 วินาทีบน CPU ทั่วไป):
  - `base` (~150 MB) — เบา แต่ภาษาไทยอาจไม่แม่น
  - `small` (~250 MB int8) — สมดุล
  - model ที่ fine-tune ภาษาไทย (เช่นตระกูล Thonburian Whisper) แปลงเป็น CTranslate2 — ต้องทดสอบเรื่องความแม่นและ license
- ใช้ `initial_prompt` ใส่ชื่อ app/mode/alias ที่มีอยู่ เพื่อช่วยให้ถอดชื่อเฉพาะได้ถูกขึ้น
- โหลด model แบบ lazy ครั้งแรกที่กด และ warm-up ใน background ตอนเปิด app
- **ไฟล์ model ไม่ฝังใน exe** — วางไว้ข้าง exe หรือใน `%LOCALAPPDATA%\AutoH\models\` (หาแบบเดียวกับ `get_data_dir`) ถ้าไม่พบ ให้ปิดฟีเจอร์เสียงแล้วแจ้งเตือน **app ส่วนอื่นยังทำงานปกติ**

## ความปลอดภัย / antivirus

- push-to-talk เท่านั้น ไมค์เปิดเฉพาะตอนกดค้าง
- action ทำได้เฉพาะที่อยู่ใน registry ไม่มี `subprocess` ที่รับ string จากเสียง
- `open_app` เปิดได้เฉพาะ path ที่มาจาก app index (Start Menu / mode / ผู้ใช้เพิ่มเอง)
- จำกัดเสียงไม่เกิน 10 วินาทีต่อครั้ง
- ไม่บันทึกไฟล์เสียงลง disk (เก็บแค่ใน memory)
- เคารพ state เดิม: ถ้า `system_paused` ให้ไม่รับคำสั่งเสียง

## ประเด็นที่ต้องตัดสินใจระหว่างทำ

1. **`already_opened`** — ตอนนี้ hotkey mode เปิดได้ครั้งเดียวจนกว่าจะ reset (`ctrl+alt+s`) คำสั่งเสียง `open_app` / `open_url` ควรติดข้อจำกัดนี้ด้วยไหม? (เสนอ: ไม่ติด, ติดเฉพาะ `run_mode`)
2. **`RUN_TIME` 20 นาทีแล้ว auto shutdown** — ยังเหมาะกับ app ที่เป็นผู้ช่วยเสียงไหม?
3. Hotkey push-to-talk ค่าเริ่มต้น: `ctrl+alt+v`?
