# แผน v2.1 — ตีความด้วย LLM + คำสั่งระบบ

> สถานะ: **แผน (ยังไม่เริ่มทำ)** · ต้องทำ [v2.0](v2.0-voice-commands.md) เสร็จก่อน

## เป้าหมาย

1. พูดเป็นธรรมชาติได้ ไม่ต้องตามรูปแบบตายตัว เช่น "เปิดไลน์กับ compass ให้หน่อย แล้วเปิด youtube ด้วย" → 3 action
2. เพิ่มคำสั่งที่มีผลกับระบบ: ปิดโปรแกรม, เสียง, ล็อกเครื่อง, sleep/shutdown — **พร้อมการยืนยัน**
3. ยังทำงานได้เมื่อไม่มีเน็ต (ถอยกลับไปใช้กฎของ v2.0)

### ไม่อยู่ในขอบเขต v2.1
- ให้ LLM สร้าง/รันคำสั่ง shell, script หรือ path ใดๆ เอง
- ควบคุมเมาส์/คีย์บอร์ด หรืออ่านหน้าจอ (computer use)
- ฟังตลอดเวลา / wake word

## ภาพรวมการทำงาน

```
ข้อความจาก STT (v2.0)
   │
   ├─▶ intent parser (กฎ) ── ตรง ──▶ actions
   │         │
   │      ไม่ตรง / มีหลายคำสั่ง
   │         ▼
   ├─▶ LLM (tool calling) ── ได้ tool calls ──▶ ตรวจ (validate) ──▶ ยืนยันถ้าจำเป็น ──▶ actions
   │         │
   │      ไม่มีเน็ต / timeout / ปิดใช้ LLM
   │         ▼
   └─▶ "ไม่เข้าใจคำสั่ง" (พฤติกรรม v2.0)
```

**กฎยังมาก่อนเสมอ** — คำสั่งง่ายๆ เร็วและฟรี LLM ใช้เฉพาะเมื่อกฎไม่พอ

## LLM: tool calling แบบปิด

- ส่งให้ LLM: ข้อความที่ได้ยิน + **รายการ tool** (= action registry) + บริบทสั้นๆ (ชื่อ app ใน index, ชื่อ mode, site ที่รู้จัก)
- LLM ตอบได้แค่ **tool calls จากรายการที่กำหนด** หรือข้อความ "ไม่เข้าใจ"
- ทุก tool call ผ่าน validator เดียวกับ v2.0 ก่อนทำงาน:
  - ชื่อ action ต้องอยู่ใน registry
  - argument ผ่าน schema (เช่น `open_app.name` ต้อง match app index — LLM ใส่ path เองไม่ได้)
  - จำกัดไม่เกิน 5 action ต่อคำสั่ง
- ไม่ต้องทำ agent loop หลายรอบ: เรียก 1 ครั้ง → ได้ list ของ action → ทำ
- ข้อมูลที่ส่งออก: **เฉพาะข้อความ** (ไม่ส่งเสียง) + ชื่อ app/mode — ต้องแจ้งผู้ใช้และให้ปิดได้
- provider/model เลือกตอนเริ่มทำ (เช่น Claude ด้วย tool use) — ออกแบบ `voice/llm.py` เป็น interface เดียวเพื่อเปลี่ยนได้
- timeout 5 วินาที → fallback

### API key
- ผู้ใช้กรอกเองในหน้า Settings
- เก็บด้วย Windows Credential Manager (`keyring`) **ไม่เก็บใน SQLite และไม่อยู่ใน Export JSON**
- ไม่มี key = ปิด LLM อัตโนมัติ (ทำงานแบบ v2.0)

## Action ใหม่

| Action | ตัวอย่างคำพูด | การทำงาน | ระดับ |
|---|---|---|---|
| `close_app(name)` | "ปิด Chrome" | หา process จากชื่อ/path ใน index → `terminate()` (ไม่ `kill`) | ⚠️ ยืนยัน |
| `set_volume(level \| delta)` | "เสียง 30", "เพิ่มเสียง" | `pycaw` | ปลอดภัย |
| `mute(on)` | "ปิดเสียง" | `pycaw` | ปลอดภัย |
| `lock_screen()` | "ล็อกเครื่อง" | `LockWorkStation` (ctypes) | ปลอดภัย |
| `open_folder(name)` | "เปิด Downloads" | เฉพาะ known folders (Desktop, Documents, Downloads, …) | ปลอดภัย |
| `sleep()` | "พักเครื่อง" | `SetSuspendState` | ⚠️ ยืนยัน |
| `shutdown()` / `restart()` | "ปิดเครื่อง" | `shutdown /s /t 30` + ปุ่มยกเลิก (`shutdown /a`) | ⛔ ยืนยัน + นับถอยหลัง |

### กฎการยืนยัน
- ⚠️ dialog "จะปิด Chrome ใช่ไหม" — Enter = ใช่, Esc / timeout 5 วินาที = **ยกเลิก** (ค่าเริ่มต้นคือไม่ทำ)
- ⛔ ยืนยันแล้วยังมีนับถอยหลัง 30 วินาทีพร้อมปุ่มยกเลิก
- ผู้ใช้ปิด action ทีละตัวได้ในหน้า Settings (เช่น ปิด shutdown ไปเลย)
- action ที่มาจาก LLM ใช้ระดับการยืนยัน **เท่ากันหรือเข้มกว่า** action จากกฎ: ถ้า LLM คืนหลาย action ให้แสดงรายการทั้งหมดก่อนทำ

## การเปลี่ยนแปลงฐานข้อมูล (schema v3)

```sql
-- settings (จาก v2) เพิ่ม key: llm_enabled, llm_provider, llm_model, disabled_actions (JSON list)
CREATE TABLE command_history (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    ts        TEXT NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now','localtime')),
    heard     TEXT NOT NULL,          -- ข้อความจาก STT
    source    TEXT NOT NULL,          -- 'rule' | 'llm' | 'none'
    actions   TEXT NOT NULL,          -- JSON ของ action ที่ตีความได้
    result    TEXT NOT NULL           -- 'done' | 'cancelled' | 'rejected' | 'error'
);
```

- prune ตาม `LOG_RETENTION_DAYS` เหมือน `logs`
- ใช้ดูว่าคำสั่งไหนตกไปที่ LLM บ่อย → เพิ่มเป็นกฎ/alias เพื่อลดค่า API
- (option) ส่ง command_history ล่าสุด 3 รายการให้ LLM เป็นบริบท เช่น "ปิดอันเมื่อกี้"

## โครงสร้างโค้ด

```
app/voice/
├── llm.py           # ใหม่: interpret(text, tool_definitions(), context) -> list[Action] | None
├── pipeline.py      # แก้: interpret() เรียก llm.py เมื่อ intents.parse() คืนค่าว่าง
├── validate.py      # มีแล้วจาก v2.0: เพิ่ม resolver ของ action ใหม่
├── confirm.py       # ใหม่: dialog ยืนยัน + countdown (Risk.CRITICAL)
└── actions.py       # มีแล้วจาก v2.0: register close_app, volume, lock, folder, power
```

ส่วนที่มีแล้วจาก v2.0 (`Action`, `Risk`, `REGISTRY`, `tool_definitions()`, `resolve()`, `execute()`) ไม่ต้องเขียนใหม่

## ชุดทดสอบความปลอดภัย (ต้องผ่านทั้งหมด)

- "รันคำสั่ง del C:\\…" / "เปิด cmd แล้วพิมพ์ …" → ไม่มี action / ถูก reject
- "เปิด C:\\Windows\\System32\\…" → reject (path ไม่อยู่ใน index)
- ประโยคที่ทำให้ LLM คืน action ที่ไม่มีใน registry → reject + log
- "ปิดเครื่อง" แล้วไม่กดอะไร → **ไม่ปิด**
- ปิด action `shutdown` ใน Settings แล้วพูด "ปิดเครื่อง" → ไม่มีผล + แจ้งว่าถูกปิดใช้

## ความเสี่ยง

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| LLM ตีความผิด → ทำผิดคำสั่ง | validator + ยืนยันเมื่อหลาย action / action อันตราย |
| ค่า API / ความหน่วง | กฎก่อนเสมอ, ใช้ model เล็ก/เร็ว, ดู command_history เพื่อย้ายไปเป็นกฎ |
| ความเป็นส่วนตัว (ข้อความออกนอกเครื่อง) | ปิดได้, แจ้งชัดใน Settings, ส่งแค่ข้อความไม่ส่งเสียง |
| `terminate()` ทำให้งานที่ยังไม่ save หาย | ยืนยันทุกครั้ง, ใช้ terminate (ให้ app ถามเอง) ไม่ใช้ kill |
| antivirus มอง power/process control เป็นพฤติกรรมน่าสงสัย | ใช้ Windows API มาตรฐาน, ไม่ inject/hook process อื่น, ทดสอบกับ Defender ตอน M5 |
